## Hello, I'm Anas

I'm a software engineer interested in what happens at the lowest levels of the GPU stack — where arithmetic throughput, memory bandwidth, and warp scheduling collide to determine whether a kernel runs fast or wastes silicon and how software can be optimized so that it helps run ML models faster.

Most of what I want to work on comes down to one question - why isn't this running faster and how can I make it run faster and more efficiently? Answering that means understanding the hardware, profiling AI workloads to find where cycles are wasted and working on compilers and tools that translate intent into code the machine actually wants to run. 

My process is: measure first, hypothesize second and then optimize. What genuinely excites me is watching the numbers climb, improving the gap between theoretical peak FLOPs and what workloads actually achieve. Closing that gap, even partially, means understanding the full picture: the ISA, the memory hierarchy, the scheduler, the interconnect - The system. That depth is what I am building. 

When I'm not reading PTX or staring at roofline plots, I'm usually deep in computer architecture papers or finding new workloads to throw at the GPU and see what breaks.

If you're working on GPU performance, AI systems, or anything low-level we could connect!
